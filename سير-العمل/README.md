# صفحة رسم سير العمل — `سير-العمل/`

رابطٌ خاص يُرسَل إلى الجهة، فيرسم فيه العميل مهمةً من عمل إدارته مرحلةً مرحلة، ويخرج بخريطتها وأرقامها وتصورٍ أوليّ لتحويلها.
ويستقبل فريقُ إذكاء ما رُسم منظّمًا في لوحته. المرجع: «إذكاء: صفحة رسم سير العمل — المواصفات وبرومبت البناء» (١٨ نوفمبر ٢٠٢٦).

## التشغيل

```bash
TEAM_KEY=مفتاح-سري PORT=8787 node سير-العمل/server/server.mjs
```

- لوحة الفريق: `http://localhost:8787/team/` (بالمفتاح `TEAM_KEY`) ومنها يُنشأ رابطٌ لكل جهة بصيغة `/r/<مفتاح>`.
- بلا خادم تعمل الصفحة وحدها والحفظُ في المتصفح فقط: `cd سير-العمل && python3 -m http.server` ثم `/?جهة=اسم الجهة`.
- الاختبارات: `node --test سير-العمل/test/calc.test.mjs سير-العمل/test/server.test.mjs`
- البيانات في `سير-العمل/data/` (أو `DATA_DIR`)، وهي خارج المستودع.

Node 22 وحده، بلا اعتماديات ولا خطوة بناء. **لم تُستضف الصفحة بعد**؛ والخادم يقدّمها من جذر النطاق.

## ما فيها

| الجزء | الملف |
|---|---|
| القوالب الثلاثة عشر، وخيارات الخصائص، وجدول قيم الحساب — منقولة من المواصفات | `js/data.js` |
| الحساب، والانتقال بين الأيدي، وقواعد «بعد التحويل» السبع — دوالّ صافية مختبَرة | `js/calc.js` |
| الرسم المشترك بين صفحة العميل ولوحة الفريق (الخريطة، والأرقام، والملف المطبوع) | `js/render.js` |
| الحالة: حفظ بعد كل لمسة، وتراجع، ودمجٌ مع الخادم لا يُضيع شيئًا | `js/store.js` · `js/sync.js` |
| صفحة العميل | `index.html` · `js/app.js` |
| لوحة الفريق: الروابط وحالاتها، ومؤشرات المسار، والنسخ الثلاث لكل مهمة، والملاحظات وحالة المتابعة، والتصدير، وتحويل المهمة إلى قالب | `team.html` · `js/team.js` |
| الخادم: الروابط الخاصة، والحفظ، والأحداث، وطلب الجلسة، وروابط الزملاء وإشعاراتهم، وحدّ الطلبات | `server/server.mjs` |
| حذف الحساس قبل التخزين (الأسماء، وأرقام القضايا، والخصوم، ووسائل التواصل) | `server/redact.mjs` |
| الترتيب الذكي: تعليمات النموذج، والتحقق من ناتجه، وواجهة المزوّد | `server/arrange/` |

## الترتيب الذكي والتفريغ: الواجهة جاهزة، والمزوّد لم يُختر

`ARRANGE_PROVIDER` و`TRANSCRIBE_PROVIDER` افتراضهما `none`: تُحفظ الحكاية ويُعرض أقرب قالب (وهو البديل عند الإخفاق في المواصفات)، ولا يظهر زرّ التسجيل الصوتي.
وإضافةُ مزوّد = ملفٌّ واحد في `server/arrange/providers/` يصدّر `complete({ system, user })` و`transcribe(buffer, mime)`.
ويُحذف الحساس قبل أن يغادر الكلامُ الخادم، ويُتحقق من الناتج: خللُ البنية يُعاد مرةً ثم يُنتقل إلى البديل، وكلُّ قيمةٍ «مذكورة» أو «مستنتجة» لا يوجد شاهدُها حرفيًّا في كلام العميل تُخفَّض إلى «غير محدد».
`fixture` مزوّدٌ للتطوير والاختبار وحدهما: ناتجٌ ثابت لمثال الحكاية في المواصفات.

## قبل الإطلاق
- عبارة «تُحفظ إجاباتك داخل المملكة» في الترحيب يجب أن تصدق على الاستضافة المختارة.
- اختيار مزوّد النموذج والتفريغ (موضع معالجة البيانات ونظام حماية البيانات الشخصية).
- تجربة ثلاثة مستخدمين حقيقيين على الأقل (المرحلة الخامسة).
